# Jev and LLM decision pipeline

Current priority: [the Abilene LLM-only baseline](ABILENE_BASELINE.md). That runner
always bypasses screening and uses an empty action catalog. The material below
describes the earlier standalone decision component and its deferred Jev adapter.

The first implementation is a decision component: an observation produces either
an unverified candidate, a request for more observations, or a no-change decision
that still needs independent evaluation. It does not collect live network state,
run Batfish, change routers, measure repair success, or roll back deployments.
Those components connect through the contracts below.

## Run the mock demonstration

From the project root, install dependencies in a project virtual environment:

```bash
uv sync
uv run python -m advnet examples/congestion.json
```

The default mock Jev explicitly escalates, and the mock LLM returns a fixture.
To exercise Jev choosing a predefined action without an LLM call:

```bash
uv run python -m advnet examples/congestion.json --mock-route avoid_r2_path
```

To exercise no intervention:

```bash
uv run python -m advnet examples/healthy.json --mock-route no_change
```

To exercise low-confidence escalation and the comparison without Jev:

```bash
uv run python -m advnet examples/congestion.json --mock-route avoid_r2_path --mock-probability 0.6
uv run python -m advnet examples/congestion.json --without-jev
```

All examples are SYNTHETIC. Router configurations come from baseline source files,
not the running containers. Measurements are invented and explicitly labeled.
Mock outputs demonstrate plumbing; they establish no model accuracy, API latency,
repair success, or cost savings. The mock route is chosen by the CLI flag, not
inferred from the observation or scenario name.

Results print as JSON and append to `runs/decisions.jsonl`. Candidate outputs
include typed changes and rendered EOS commands. No command is executed.
Each live request records the resolved model, available token usage, and SDK-call
wall time. Usage missing from a provider is unknown, not zero. Dollar cost and
repair success remain null; billing and independent outcome evaluation must
supply them. Errors retain the error class but omit provider exception text to
avoid logging credentials or full request payloads. No model reasoning trace is
requested; `diagnosis` and `evidence` are concise operational explanations.

## Real providers

```bash
uv sync --extra live
```

Set credentials in your terminal or secret manager. `.env.example` lists variable
names; `.env` is ignored by Git but is not loaded automatically. Do not paste
credentials into chat, example observations, or configuration files.

- Jev uses `TYPESAFE_API_KEY` through the official `typesafe-sdk`.
- OpenAI and OpenAI-compatible servers use `OPENAI_API_KEY` through the `openai` SDK.
- Anthropic uses `ANTHROPIC_API_KEY` through the `anthropic` SDK.
- A local compatible server may accept a dummy API-key value.

Choose an exact model ID available to your account; replace MODEL_ID below:

```bash
uv run python -m advnet examples/congestion.json --mode live --llm-provider anthropic --llm-model MODEL_ID
uv run python -m advnet examples/congestion.json --mode live --llm-provider openai --llm-model MODEL_ID
uv run python -m advnet examples/congestion.json --mode live --llm-provider compatible --base-url http://localhost:8000/v1 --llm-model MODEL_ID
```

Live mode sends the supplied observation and catalog to the selected providers.
Use a sanitized observation from the collector when ready to test real state.
The commands above still use a synthetic fixture, and still only produce a
candidate. Qwen requires an existing compatible model server or hosted endpoint;
this project does not download or host model weights.

`--jev-model` defaults to `jev-latest`. Pin a model version and retain the `uv.lock`
generated by a successful `uv sync` for experiments. The planned Haiku, Astra, Fable, and Qwen names should be mapped
to account-supported identifiers before trials; labels are not silently replaced.
There are no model-specific reasoning settings yet, so do not claim matched
reasoning budgets across providers. The OpenAI adapter uses Responses with
`store=False`; the compatible adapter uses Chat Completions. Anthropic uses the
Messages API. All adapters request JSON, validate it locally, reject truncated
responses, and disable SDK retries so implicit retries do not distort call counts.
Live API behavior and model availability still require credentialed testing.

## Jev routing and supported changes

Jev makes a closed choice among `no_change`, `escalate`, and catalog action IDs.
The full current observation and bounded catalog are supplied as state. Catalog
selection instantiates an existing patch; Jev does not generate commands.

`--threshold` defaults to 0.9 and applies to the probability of the selected option,
not the separate SDK confidence value. This is an uncalibrated starting parameter;
tune it on development scenarios and evaluate on held-out scenarios. Invalid
probabilities, unknown choices, low probability, and Jev errors escalate to the
LLM. Feedback from a previous attempt also forces escalation in this initial
version. A false no-change decision is possible and must count against the system
in independent evaluation; it does not certify health.

The sample catalog is specific to the diamond. It offers moving traffic away
from R2 by setting R1/R4 Ethernet1 costs to 300, or restoring costs to 10. These
are illustrative actions, not verified repairs. Intended traffic changes must be
measured under the same offered load with throughput and loss guardrails.
Review the catalog and explicit policies before using a different topology.

Initial patches support only:

- OSPF interface cost, integer 1 through 65535.
- OSPF area in dotted IPv4 notation.
- Interface administrative enable/disable.

Device and Ethernet interface names must exist in the observation. Management,
ACL, arbitrary CLI, and shell changes are rejected. Rendered commands omit
`configure terminal`, `end`, and persistence commands; the deployment controller
owns command context and checkpointing. Reassigning OSPF areas or disabling
interfaces can disrupt service, so schema validity never substitutes for Batfish
or live acceptance. More protocols/actions can extend this explicit contract.

## Partner integration contract

`advnet/contracts.py` defines strict Pydantic schemas; JSON schemas are in
`docs/schemas/`. Unknown fields and unsupported patch types are rejected.

1. The collector provides an `Observation`: scenario ID, timestamp, operator
   objective, explicit requirements, topology, device/interface inventory,
   configurations, telemetry, and measurements. It excludes injected-fault labels,
   hidden test outcomes, and ground-truth repairs.
2. `DecisionEngine.decide(observation, feedback, attempt)` returns a decision ID,
   proposed changes, model timings/usage, and a handoff:
   - `verification_required`: the partner builds the candidate snapshot and
     verifies intended policies before deployment.
   - `collector_required`: obtain requested evidence, then call the decision
     component with refreshed observations.
   - `independent_evaluation_required`: evaluate a no-change claim independently.
   - `none` with `decision_error`: do not deploy anything; record the failed decision.
3. Verification or runtime rejection returns a `Feedback` record with the prior
   decision ID in `candidate_id`, stage, attempt, acceptance, specific details,
   and measurements. Runtime rejection also reports whether rollback succeeded.
4. On retry, pass a fresh observation and all earlier feedback. Runtime rejection
   with unconfirmed rollback blocks the next proposal. Runtime acceptance ends
   the trial. The caller is responsible for authenticating and correlating
   feedback with the correct scenario, decision ID, and network checkpoint.

Example feedback plumbing (uses an explicitly illustrative rejection):

```bash
uv run python -m advnet examples/congestion.json --attempt 2 --feedback examples/rejection.json
```

The controller owns the overall monotonic time deadline, actual five-attempt
budget, network locking, fresh observations, and the verify/deploy/measure/
rollback lifecycle. This CLI performs ONE decision per invocation. `--attempt`
checks range and feedback order, but is not a persistent global budget. A per-call
SDK timeout is not an overall trial time cap. Do not infer a completed closed
loop from this decision component. Repeating a rejected patch is discouraged by
the prompt; tracking/rejecting repeated candidate fingerprints belongs in the
trial harness and is not enforced here yet.

For the Jev ablation, keep the same observations, catalog, LLM, policies, traffic,
retry budget, and deployment checks, then use `--without-jev`. Have the evaluation
harness assign scenario/run identifiers consistently and track failures as well
as successes. Full observations can remain outside the decision log; the log's
SHA-256 input digest supports correlation but does not replace saving sanitized
inputs for reproducibility. Screening error rate, escalation rate, LLM calls,
model-request latency, full recovery time, and cost per successful repair are
separate quantities.
